# Chromora Rust 0.7 JPEG 精度修复版

2026-11-07：新导入照片使用 `accurate_srgb`，JPEG 使用 libjpeg-turbo 解码并接续原有高精度 ICC 到 sRGB 转换。0.6 照片的 `hq_srgb` 和更早照片的 `legacy_srgb` 保留原处理；打开旧工程不会自动改变颜色。当前保存 schema6，旧 schema1–5 和 Python 工程首次保存必须另存为新文件，建议名为 `工程名-0.7.chromora`。

使用和兼容说明见 `WORKFLOW07.md`。原夹具、原色差门槛的实际复验及正式构建身份以交付验证报告为准；本说明不代表所有 JPEG、ICC、相机或显示器已完成验收。撰写当时 Cargo 包内部版本为 0.1.0；自 0.10.1 起与产品版本一致。

## 0.6 精度优化版历史记录

2026-11-07：本轮完成第一批色彩优化的实现。新导入的 8 位 RGB 图像在 ICC 转换前无损映射到 16 位，复用高精度转换后保存为 float32；输入 ICC 损坏、不支持或转换失败时明确拒绝。工作与导出色域仍为 sRGB。使用说明见 `WORKFLOW06.md`，最终构建、色差复验、旧工程像素兼容和 GUI 结果以交付目录中的 `精度优化验证报告.md` 为准。

- “信息”面板显示源 ICC 摘要和实际色彩处理状态，包括无 ICC 按 sRGB 解释、ICC 已转换为 sRGB、RAW 显影为 sRGB，以及旧工程兼容时的 ICC 未转换状态。新导入失败会显示原因，没有自动降级打开选项。
- 当前保存格式为 schema5，每张照片分别记录 `hq_srgb` 或 `legacy_srgb`。旧 schema1/2/3/4 和 Python 工程继续使用旧版处理，新导入照片使用高精度转换；同一工程可以保留两种照片。旧工程的颜色不会因打开而自动升级。
- 打开旧工程后首次保存会进入另存为流程，建议文件名为 `工程名-0.6.chromora`；核心同时拒绝用 schema5 覆盖旧格式工程。新版工程保留每图处理版本和撤销／重做历史，之后可正常更新保存。0.5 及更早版本不能读取 schema5，请保留原工程。
- 16 位 PNG、TIFF、JPG、双像素层 PSD、Patchy 交接及其它修图工具沿用现有工作流程；RAW 解码数值算法本轮未改。8 位来源映射为 16 位用于减少转换量化，不增加原片本来没有的细节。

本轮没有实现端到端广色域工作缓冲、P3／Adobe RGB／ProPhoto 目标导出或逐显示器色彩管理。色差改善幅度和通过范围以本轮验证报告为准，不由“高精度”名称推断。

以下保留 0.5 及更早版本历史说明；撰写 0.6 说明时的工程格式、ICC 异常处理和色彩处理版本以当时页首及 `WORKFLOW06.md` 为准。0.6 是当时的功能交付编号。撰写当时 Cargo 包内部版本为 0.1.0；自 0.10.1 起与产品版本一致。

## 0.5 改进版历史记录

2026-11-07：在 0.4 工作流版上加入 RGB16 无损 PNG 导出，修复 RAW 导入名单与部分元数据缺失，增强有损 DNG／X3F 解码，并将撤销和重做历史保存到工程。使用方法见 `WORKFLOW05.md`；当前能力及边界见 `PARITY.md` 顶部。最终构建、样本复验、GUI 和交付文件身份以交付目录中的 `修复验证报告.md` 为准。

- 输出支持 JPG、16 位 PNG、16 位 TIFF、双像素层 PSD，以及 Patchy 的 TIFF 交接。PNG 为完整分辨率、带 sRGB ICC 的 RGB16 无损文件，不含透明通道；导出拒绝覆盖原片或已有目标。
- RAW 导入入口与核心统一为 27 种扩展名，补齐 CRW、DCR、FFF、K25、MOS、RWL、SR2、SRF。增强 LibRaw 仍为 0.22.3，启用 JPEG 和 X3F；原有 EXIF 优先，只用解码器实际读到的信息补缺。
- 新版应用保存 schema4 工程，包含每张照片合计最多 100 步的撤销／重做记录；读取旧 schema1/2/3 和原 Python 工程。保存后关闭再重开，可继续撤销和重做；旧版应用不能读取新 schema4，建议旧工程另存。
- Windows 数据目录优先使用可写的 `D:\修图软件`；无 D 盘或实际数据目录不可写时，回退至 `%LOCALAPPDATA%\Chromora`。左侧“项目”面板显示实际数据目录。两个位置均不可用时明确报错。
- 运行不需要 Python、Node 或浏览器。便携交付在 `Release` 同目录部署官方 VC 运行库，减少预装运行库的要求；保留同目录 DLL 后启动 `Release/chromora.exe`。

RAW DLL 的实际支持声明为 1,274 条，这个数字不是全机型验收通过数。真实干净 Windows、真实多屏、所有固件／RAW 变体及独立色彩准确性仍需相应环境与样本验证。内部工作缓冲继续采用 float32 sRGB。

以下为 0.4 及更早版本的历史说明；其中历史保存范围、数据目录和支持状态以撰写 0.5 说明时的页首、`WORKFLOW05.md` 和该轮验证报告为准。0.5 是当时的功能交付编号。撰写当时 Cargo 包内部版本为 0.1.0；自 0.10.1 起与产品版本一致。

## 0.4 工作流版历史记录

以下 0.3 说明记录已有基础能力，schema 以本段和交付报告为准。

2026-11-06：已将原 Python 版 0.3 的已交付模块迁入 Rust + GPUI。当前实现和限制见 `PARITY.md` 顶部，最终测试、界面实测和文件身份以交付目录中的迁移验证报告为准。

运行时不需要 Python、浏览器或 Node。打开交付目录 `Release/chromora.exe`，数据继续使用 `D:\修图软件`。导出和个人预设拒绝覆盖已有目标；原片不写入调整。

- 导入 JPG/PNG/TIFF/RAW，可多选、目录导入或拖放，底部胶卷切换照片。
- 基础、曲线/HSL/分级、细节、人像、风格、工程和照片信息位于左侧面板；先快速预览，100%/200% 停手后更新全图。
- 分屏拖动比较，画布获得焦点后按住空格看原图。皮肤选区可拖出后确认，方向键移动、Shift+方向键改大小、Enter 确认、Esc 取消。
- 风格支持独立 sRGB 3D `.cube`、收藏、强度和成片微调。工程和预设使用文件名命名。
- JPG 为 8 位质量96/4:4:4；TIFF 为 RGB16/Deflate；PSD 为8位 Original/Edited 两像素层和合成预览。三者嵌入 sRGB ICC。参数保存在工程。
- 新工程 schema2，兼容 Rust schema1。旧 Python JSON 从原 `数据/工程` 目录打开，以定位原片、显影缓存和风格；另存 `.chromora`，保留旧 JSON。

LibRaw 0.22.3 DLL、同版头文件和许可位于 `native/libraw`。来源及 SHA 见该目录 `SOURCE.md`。需要 Windows x64 VC 运行库；Patchy 使用 D 盘现有完整便携目录。源码构建需要 MSVC、Windows SDK、Rust1.89，`build.rs` 编译薄 RAW 桥接。

主要工作缓冲为 float32 sRGB，保持旧版算法语义，不是全程场景线性广色域显影。有效 ICC 尝试转 sRGB；异常/不支持的 profile 沿用解码 RGB 回退。RAW 机型、跨色域和干净电脑等边界见验证报告。

## 当前状态

首个纵切片为 JPG/PNG → EXIF 方向与只读照片信息 → sRGB8 工作像素 → 线性光曝光 → 工程保存/重开 → JPG 导出。

- 首期支持 8-bit JPG/PNG；任何透明/半透明像素会明确报错。含 alpha 但 alpha 全为 255 的 PNG 可导入。
- 有效嵌入 ICC 尝试转换到 sRGB；无 ICC 按解码 RGB 处理；无效或当前转换器不能处理的 profile 走解码 RGB 回退。输入 profile 摘要可供只读照片信息显示。
- RAW、16-bit TIFF、PSD、旧版 0.3 工程兼容、各品牌相机色彩与 UI 全功能 parity 尚未实现。
- 2026-11-05 已在 Windows 11 上通过 Debug 原生构建及 28 项自动测试，并复验原片保存保护、未保存确认、100%/200% 缩放与加载期间编辑互斥。详见 `WINDOWS_FIXES.md`。Release、多显示器及跨色域准确性仍未验收。

## 本地构建与测试

```sh
cargo check --all-targets
cargo test --all-targets
```

GPUI 0.2.2 的 Linux build 需要系统图形开发依赖。当前验证环境使用 X11/Wayland 后端，并安装 `libxkbcommon-dev`、`libxkbcommon-x11-dev`。Windows 用户数据根目录设计为 `D:\修图软件`，Linux 和测试使用独立目录或注入临时根路径。

## 结构

- `src/core/`：与 GPUI 无关的图像、PhotoInfo、曝光、工程、导出逻辑。
- `src/app.rs`、`src/main.rs`：GPUI 应用/窗口/controller 与异步操作。
- `src/ui/`：自然暗房工作台和主题。
- `fixtures/`、`tests/`：固定像素、EXIF、ICC、透明 PNG 和 project/API contracts。
- `PARITY.md`：与旧版功能清单逐项的实现状态和后续验收门槛。
